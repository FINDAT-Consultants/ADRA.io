ADRA UNIFIED WORK EVIDENCE & RECOVERY PASSPORT SYSTEM
===================================================

CURRENT ACCESS
--------------
The application currently opens directly without sign-in, account creation or profile creation.

THE FOCAL POINT
---------------
The two systems are merged around one shared object: the WORK-EVIDENCE SPINE.

Master Time Schedule (MTS) captures the operational evidence:
- employee / department / project
- clock-in and clock-out
- actual elapsed hours
- activity description
- location evidence
- supporting document metadata/body for small files
- completion percentage
- on-time review
- delay/challenge comments

When a work session is completed, the system creates a DRAFT Recovery Passport time entry. The deterministic workbook engine then performs daily reconciliation, project eligibility, monthly expected-hours/payroll allocation, exception checks, and the five-key Recovery Passport gate.

The Recovery Agent reasons across operational MTS evidence, recovery evidence, foundational knowledge, persistent memory and stored records. It can execute enabled tasks through auditable tools.

OPENAI KEY SETUP
----------------
A real OpenAI API key must NEVER be embedded in this project ZIP or browser code.
If a key has been pasted into chat, source code, email, or another exposed location, rotate/revoke it and create a fresh project key.

Server setup:
  copy .env.example to .env
  set OPENAI_API_KEY=<new rotated project key>
  set OPENAI_MODEL=gpt-5.6       (or another supported model you intentionally deploy)
  npm start

The .env file is ignored by Git and should remain server-only.

Verification:
  npm run verify-intelligence
  npm run verify-security

============================================================
SYSTEM REASONING BRAIN / PROACTIVE AI ADVISOR
============================================================

When the application server is running, each signed-in user receives a persistent System Brain conversation.

Capabilities:
- natural back-and-forth and casual conversation in Recovery Agent
- context carried across follow-up messages and corrections
- causal cause → mechanism → consequence analysis without confusing correlation with causation
- deterministic mathematics, statistics and probability verification for quantitative questions
- general non-current knowledge answers plus live evidence/recovery reasoning for system questions
- predictive compose suggestions with estimated relative continuation probabilities
- proactive ADRA AI Advisor notifications when actionable system conditions change
- Reply from an AI notification into the same user conversation
- automatic de-duplication and clearing of stale AI notifications after the underlying condition is resolved
- human approval remains mandatory for controlled system changes

Optional monitor interval:
  AI_ADVISOR_SCAN_MS=45000

Recommended production setup:
  OPENAI_API_KEY=<server-side project key>
  OPENAI_MODEL=<supported model selected for your deployment>
  AI_ADVISOR_SCAN_MS=45000

Verification:
  npm run verify-brain
  npm run verify-reasoning


============================================================
ACTIVE RECOVERY AGENT / LOCAL SERVER MODE
============================================================

The Recovery Agent intentionally does not run a canned browser fallback anymore.
For real LLM conversation and task execution, always run the Node server:

Windows:
  1. copy .env.example .env
  2. edit .env and set OPENAI_API_KEY=<fresh rotated server-side key>
  3. double-click start-local.bat

macOS/Linux:
  1. cp .env.example .env
  2. edit .env and set OPENAI_API_KEY=<fresh rotated server-side key>
  3. chmod +x start-local.sh
  4. ./start-local.sh

Then use http://localhost:3000. Opening index.html directly with file:// cannot securely run the OpenAI Agent.

When the Agent executes a supported command, the browser shows a live activity trace that opens the relevant feature/panel and highlights the control while the server-side tool performs the audited change. Explicit approve/reject commands can act on an assigned review when the signed-in user has reviewer authority. Failed deterministic controls and journal posting cannot be overridden. Successful Agent tasks create an unread ADRA AI Advisor notification.

Verification:
  npm run verify-execution


OPENAI EXECUTION AND ACCESS CONTROL
-----------------------------------
OpenAI-powered agent tasks use @openai/agents with OPENAI_API_KEY from the deployed server environment. There is no local-model or canned AI fallback. Do not place the OpenAI key in browser code.

Application roles: Developer, Administrator, Employee. The hidden bootstrap Developer username is Dvp and the requested default password form Abcd\@1234 is accepted. Set DEVELOPER_BOOTSTRAP_PASSWORD before production deployment to replace the default. Administrators are company-scoped; Employees receive restricted views and own-record controls.
