ASSURANCE REGENT — SUPABASE-ONLY LIVE SYSTEM
============================================

WHAT CHANGED
------------
The live Assurance Regent system no longer uses browser localStorage as a durable database.
Supabase is now required for live persistent operation.

Supabase stores:
- user accounts and password hashes
- hashed authenticated session registry
- companies, roles, settings and profiles
- live employees, projects, payroll, calendar, time entries, recruiting and onboarding state
- MTS work sessions and internal messages
- Recovery Agent memory, conversations, activity traces and learned mappings
- stored records/tasks/action audit logs
- controlled document metadata

Supabase Storage stores:
- uploaded controlled documents and MTS supporting documents

Live authentication uses a short-lived HttpOnly cookie. The session registry and hashed token identifiers are stored in Supabase. Direct file:// preview is memory-only and does not write durable user/application data to browser storage.

SUPABASE DATABASE SETUP — BROWSER ONLY
--------------------------------------
1. Open your Supabase project.
2. Open SQL Editor.
3. If this Supabase project already contains Assurance Regent data, open:
   supabase/ASSURANCE_REGENT_EXISTING_PROJECT_UPDATE.sql
   This is the non-destructive upgrade path.
4. If this is a brand-new/empty Supabase project, open instead:
   supabase/ASSURANCE_REGENT_COMPLETE_SETUP.sql
5. Copy the correct file into the Supabase SQL Editor and click Run.
6. Confirm the private Storage bucket named assurance-regent-files exists.
7. Do not run the fresh/empty combined setup over an existing live database because its workbook seed refreshes the supplied foundation tables.

SERVER ENVIRONMENT
------------------
Configure these values in the environment/settings of the service that runs server.js:

SUPABASE_URL=https://fubqwljypdiojpbdunjc.supabase.co
SUPABASE_SECRET_KEY=<your current Supabase secret key>
SUPABASE_STORAGE_BUCKET=assurance-regent-files

Optional AI configuration:
OPENAI_API_KEY=<your server-side OpenAI key>
OPENAI_MODEL=gpt-5.6

SECURITY
--------
Never place SUPABASE_SECRET_KEY in GitHub, index.html, app.js, public/app.js or any browser JavaScript.
Supabase secret keys bypass Row Level Security and must remain server-side.
If a secret key was previously committed or exposed publicly, rotate it before deployment.

IMPORTANT DEPLOYMENT NOTE
-------------------------
Assurance Regent is a full-stack application. A static-only host cannot run server.js.
The GitHub repository can hold the project source, but the live deployment must run the Node server (or an equivalent server deployment) so the Supabase secret key remains protected and all persistent API calls reach Supabase.
