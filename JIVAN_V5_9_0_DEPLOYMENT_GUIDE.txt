ASSURANCE REGENT — JIVAN v5.9.0 DEPLOYMENT GUIDE
=================================================

WHAT THIS RELEASE ADDS
----------------------
1. Recovery Agent is now named Jivan in the user interface and system prompt.
2. Jivan recognizes direct address such as "Jivan", "Hey Jivan", "Hi Jivan" and "Okay Jivan" in typed or transcribed voice instructions.
3. Foreground multi-step work capacity is expanded while preserving role and confirmation guardrails.
4. A persistent Supabase-backed delegated task queue allows Jivan to perform non-interactive background work while the signed-in user continues elsewhere in Assurance Regent.
5. Background-safe work includes public research, role-scoped exports, report/document preparation, research visualizations and review of already stored/available documents.
6. File-upload instructions can open the correct chooser. After the user selects a local file, Assurance Regent automatically continues the configured upload/analyze workflow.

IMPORTANT LOCAL-FILE BOUNDARY
-----------------------------
A browser cannot silently browse Windows/macOS/Linux drives and select an arbitrary local file on the user's behalf. The operating system/browser requires the user to select or grant access to a local file. Jivan can initiate the chooser and continue automatically after selection. This security boundary is intentionally preserved.

BACKGROUND-WORK BOUNDARY
------------------------
The v5.9.0 queue is persistent in Supabase, so task state survives refresh/reload. The in-browser worker processes queued tasks while Assurance Regent remains open and signed in. If the browser/tab is closed, queued work remains stored and resumes when Assurance Regent is opened again; a task interrupted while marked RUNNING is eligible for recovery after the stale-worker timeout. True server-side execution while every browser is closed would require an additional scheduled/worker service and is not claimed by this release.

DEPLOYMENT
----------
1. Make sure the earlier Assurance Regent database upgrades are already installed, including:
   - DEVELOPER_GOVERNANCE_V5_4_0.sql
   - LEAVE_WORK_STATUS_V5_8_0.sql

2. Supabase -> SQL Editor -> New query.
   Run the entire file:
   JIVAN_BACKGROUND_TASKS_V5_9_0.sql

3. Run:
   JIVAN_BACKGROUND_TASKS_V5_9_0_VERIFY.sql
   Confirm schemaVersion = 5.9.0 and ready = true.

4. Upload the CONTENTS of ADRA.io-main-v5.9.0-complete.zip to the GitHub repository connected to Netlify.
   Netlify continues to publish the public/ directory.

5. Supabase -> Edge Functions -> recovery-agent.
   Replace the deployed function with the v5.9.0 RECOVERY_AGENT_EDGE_FUNCTION.ts and deploy it.
   Keep the existing OPENAI_API_KEY secret server-side.

6. Hard-refresh the deployed Assurance Regent site after Netlify finishes.

TESTS
-----
A. Type or say: "Jivan"
   Expected: Jivan acknowledges the name and asks what you need.

B. Say: "Jivan, open Payroll and wait for me."
   Expected: normal role-authorized navigation.

C. Say: "Jivan, research the latest information on [topic] and prepare a PDF in the background while I continue working."
   Expected: Jivan delegates the task, the background-task badge shows active work, and the current page is not taken over by the research task.

D. Move to another Assurance Regent section while the background task runs.
   Expected: no forced navigation from the delegated task. Completion appears in the Jivan conversation/task list.

E. Say: "Jivan, upload my report.pdf and analyze it."
   Expected: the file chooser opens. Select report.pdf once. After selection, Assurance Regent automatically sends it through the configured analysis workflow without another Send click.

F. Try a sensitive command such as account suspension, company shutdown, approval/rejection or deletion.
   Expected: the existing role and explicit-confirmation guardrails still apply. These operations are not silently delegated to background work.

SECURITY
--------
- Jivan does not receive arbitrary JavaScript or unrestricted SQL execution.
- Employee, Administrator and Developer role boundaries remain enforced.
- Local file selection remains controlled by the OS/browser.
- Purchases, sign-out, approval/rejection, role changes, account/company suspension and destructive operations remain foreground/confirmation-gated.
- The OpenAI secret stays in Supabase Edge Function Secrets, never in frontend code.
