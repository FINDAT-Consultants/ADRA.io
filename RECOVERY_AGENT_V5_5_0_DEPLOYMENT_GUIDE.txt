ASSURANCE REGENT / ADRA.io — RECOVERY AGENT v5.5.0 DEVELOPER GOVERNANCE

WHAT THIS UPDATE DOES
=====================
Recovery Agent can now carry out the Developer Governance controls added in v5.4.0 using exact account/company targeting rather than generic button guessing.

DATABASE
========
No new SQL is required if DEVELOPER_GOVERNANCE_V5_4_0.sql has already been run successfully.
The v5.5 Agent uses the existing secured RPCs created by v5.4.0:
- assurance_regent_browser_admin_account_status
- assurance_regent_browser_admin_update_user
- assurance_regent_browser_admin_delete_user
- assurance_regent_browser_admin_company_access
- assurance_regent_browser_agent_audit_append

DEPLOYMENT
==========
1. Upload the contents of ADRA.io-main-v5.5.0-complete.zip to the GitHub repository used by Netlify.
2. Let Netlify deploy the updated public/ directory.
3. In Supabase > Edge Functions > recovery-agent, replace the current function code with RECOVERY_AGENT_EDGE_FUNCTION.ts from this v5.5 package and deploy it.
4. Keep the existing OPENAI_API_KEY secret and existing Recovery Agent settings.
5. Keep legacy Verify JWT disabled if your current Assurance Regent setup uses its database-backed session token, as in the previous v5 releases.
6. Hard-refresh the browser after Netlify finishes.

TESTS
=====
Sign in as a Developer and try these in order:

A. Pending account
   "Recovery, open notifications and confirm <name>'s account."
   Expected: Notifications opens, the exact pending account is confirmed, the notification disappears, and the user can sign in.

B. Suspend / reactivate
   "Recovery, open settings and suspend <name>'s account."
   Expected: Settings opens, a browser confirmation appears, then the account is suspended and active sessions are blocked.
   Then: "Recovery, reactivate <name>."

C. Company service
   "Recovery, switch <company> offline."
   Expected: Settings opens, the exact company is selected by ID in the governance action, a final warning is shown, then the company is switched OFF.
   Then: "Recovery, switch <company> back online."

D. Billing
   "Recovery, set <company>'s monthly amount to ZMW 8500 and payment details to <details>."
   Expected: Settings opens and the existing company service RPC saves the new billing values.

E. Developer role
   "Recovery, make <user> a Developer."
   Expected: Settings opens, a strong confirmation appears, then the exact account is assigned Developer authority.

SECURITY NOTES
==============
- Administrator and Employee Recovery Agents do not receive Developer governance tools.
- The permanent Dvp account remains protected.
- Password reset is intentionally not an autonomous AI tool; passwords stay in the visible Developer Settings workflow.
- High-impact actions require explicit wording from the current Developer instruction and additional browser confirmation where appropriate.
- Governance actions are written to the Recovery Agent audit log.
