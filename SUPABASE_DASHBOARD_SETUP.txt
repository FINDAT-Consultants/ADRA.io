ASSURANCE REGENT — SUPABASE-ONLY PERSISTENCE SETUP
=================================================

All Supabase database setup is completed in the browser through the Supabase Dashboard.

1. Open your Supabase project in the browser.
2. Open SQL Editor.
3. Existing project with live Assurance Regent data: open supabase/ASSURANCE_REGENT_EXISTING_PROJECT_UPDATE.sql.
4. Brand-new/empty project only: open supabase/ASSURANCE_REGENT_COMPLETE_SETUP.sql.
5. Copy the correct file into the SQL Editor and click Run. The fresh combined setup contains the workbook seed, so do not use it as an upgrade over live data.
6. Confirm that these key objects exist:
   - public.assurance_regent_state
   - public.assurance_regent_auth_sessions
   - public.mts_work_sessions
   - public.mts_messages
   - public.agent_memories
   - public.agent_session_items
   - public.system_records
   - public.agent_action_log
   - public.agent_learning_mappings
   - Storage bucket: assurance-regent-files (Private)
7. In the environment/settings of the server that hosts Assurance Regent, set:
   SUPABASE_URL=https://fubqwljypdiojpbdunjc.supabase.co
   SUPABASE_SECRET_KEY=<your current Supabase secret key>
   SUPABASE_STORAGE_BUCKET=assurance-regent-files
8. Do NOT place SUPABASE_SECRET_KEY in GitHub, index.html, public/app.js, or any browser JavaScript.
9. Deploy/restart the server and sign in. New users and all live system changes will now use Supabase as the durable system of record.

IMPORTANT
---------
The supplied project intentionally does not contain your real Supabase secret key. If a secret key has previously been pasted into source code or committed publicly, rotate it in Supabase before deployment.

Directly double-clicking index.html uses preview mode only. Preview mode no longer writes durable data to the browser. Full persistent operation must run through the connected application server so the Supabase secret remains server-side.
