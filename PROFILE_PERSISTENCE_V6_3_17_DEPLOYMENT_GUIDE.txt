ASSURANCE REGENT v6.3.17 — PROFILE SAVE HOTFIX

Problem fixed
- Profile Save could throw: Cannot read properties of undefined (reading 'currentUser').
- The Control Center state stored operational settings but did not guarantee a profile.currentUser object.
- The permanent Developer identity is synthesized at runtime, so changing its name/email/photo in the old client was not durable.
- Normal users also needed a governed server-side path for changing their own name/email/photo.

Deploy in this order
1. Open Supabase -> SQL Editor.
2. Run PROFILE_PERSISTENCE_V6_3_17.sql once.
3. Optional: run PROFILE_PERSISTENCE_V6_3_17_VERIFY.sql. All three columns should return true.
4. Deploy the /public folder from this package to Netlify (or redeploy the project normally).
5. Hard-refresh the browser once (Ctrl+Shift+R), sign in, open Profile, select a picture, enter the email/name, and click Save profile.

Expected result
- Toast: Profile saved to Supabase.
- The profile picture remains after refresh/sign-out/sign-in.
- Display name and email remain after refresh/sign-out/sign-in.
- Developer, Administrator and Employee profiles use the same governed RPC.
- Duplicate email addresses are rejected.
- Direct table access remains blocked; the browser only receives execute permission on the scoped RPC.

Important
The frontend deliberately reports a clear message if the SQL hotfix has not yet been installed. The Netlify deployment and Supabase migration are both required for the complete fix.
