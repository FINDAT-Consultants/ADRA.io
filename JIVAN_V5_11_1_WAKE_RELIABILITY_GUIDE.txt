JIVAN v5.11.1 — WAKE RELIABILITY HOTFIX

Purpose
-------
This update fixes cases where the interface showed Wake mode as enabled but the underlying browser speech recognizer had stopped or gone idle.

What changed
------------
1. Jivan now restarts the wake recognizer automatically when the browser ends it.
2. A health watchdog reconnects the listener if it is no longer active.
3. Jivan recognizes his name from interim as well as final speech-recognition results.
4. Common recognition variants are accepted: Jivan, Jeevan, Jevan, Jeevin, Jiven, Jivaan and Givan.
5. If the browser speech-recognition service is unavailable or repeatedly fails, Jivan can use the already-authorized microphone stream with voice-activity detection and the existing Supabase/OpenAI transcription route to detect the wake word.
6. The UI now shows Wake: listening only when a real wake engine is active. During recovery it shows Wake: reconnecting.

Test
----
1. Deploy the v5.11.1 files to the HTTPS Assurance Regent site.
2. Sign in and ensure microphone permission has previously been granted.
3. Confirm the Jivan control shows Wake: listening.
4. Do not press Mic. Say: Jivan.
5. Jivan should answer: Yes. I'm listening.
6. Speak a command. After you stop speaking it should submit directly.
7. Leave the page idle for one minute and repeat the test. The listener should have self-recovered if the browser ended its recognition session.

Browser boundary
----------------
A website cannot bypass a browser's first microphone permission decision. Wake mode only starts automatically after the Assurance Regent origin has already been permitted to use the microphone. Background/hidden-tab microphone behavior can also be limited by the browser/operating system.

No new Supabase SQL or Edge Function deployment is required for v5.11.1.
