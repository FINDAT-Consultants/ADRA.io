ASSURANCE REGENT / JIVAN v5.10.0 — DEPLOYMENT GUIDE

WHAT THIS UPGRADE ADDS
- Newest-first paginated tables: latest records appear on page 1; older records move to later pages.
- Functional authority: HR Manager, Finance Manager, Project Manager, Programs Manager/Director, CEO.
- CEO is overall company authority. Developer remains the system-wide highest authority.
- HR leave approval/rejection and leave-policy management.
- Finance payroll/finance review scope.
- Project/Programs managed-team and project review scope.
- Managed-team visibility for relevant company/time/work data.
- Company-registration country drives Leave & Work Status country label.
- Clear Conversation no longer repopulates the chat with background-task completion messages.
- Explicit Jivan sign-out commands execute immediately.

DEPLOYMENT ORDER
1. Your existing database must already contain the previous Assurance Regent upgrades, including:
   - DEVELOPER_GOVERNANCE_V5_4_0.sql
   - LEAVE_WORK_STATUS_V5_8_0.sql
   - JIVAN_BACKGROUND_TASKS_V5_9_0.sql

2. Supabase > SQL Editor > New query. Run the entire file:
   DEPARTMENTAL_AUTHORITY_V5_10_0.sql

3. Run:
   DEPARTMENTAL_AUTHORITY_V5_10_0_VERIFY.sql
   Confirm schemaVersion = 5.10.0 and ready = true.

4. Deploy the CONTENTS of ADRA.io-main-v5.10.0-complete.zip to the GitHub repository used by Netlify.

5. Supabase > Edge Functions > recovery-agent. Replace its code with the v5.10.0 RECOVERY_AGENT_EDGE_FUNCTION.ts and deploy it. Keep OPENAI_API_KEY in Supabase Secrets.

6. Hard-refresh the deployed site after Netlify finishes.

ASSIGNING FUNCTIONAL AUTHORITY
- Developer can assign CEO and any departmental authority.
- CEO can assign HR Manager, Finance Manager, Project Manager, Programs Manager/Director and lower company authority.
- A normal Administrator cannot grant Developer, CEO, or senior departmental-manager authority.
- Developer is the only level allowed to create/promote Developer authority.

REGISTERED COUNTRY
New companies require a Registered country when created. For companies that existed before v5.10.0, the historical registration country cannot be inferred safely. Sign in as Developer, open Control Center > Settings > Company service directory, choose the correct Registered country and click Save service status once. Leave & Work Status will then show that country. Once recorded, v5.10 treats it as the original registration country and does not allow casual country changes through the normal service-directory control.

TESTS
A. Create several records with different dates and verify page 1 shows the newest.
B. Assign an HR Manager and confirm Leave approval/rejection is available but payroll is not.
C. Assign a Finance Manager and confirm Payroll/finance reviews are available without HR recruiting context.
D. Assign a Project/Programs Manager and verify employee/time/work lists are restricted to managed staff where applicable.
E. Assign CEO and verify company-wide operational access; verify Developer-only system authority remains separate.
F. Run a background Jivan task, let it complete, then use Clear Conversation. The main Jivan conversation should remain clear; task results remain available only in Background Tasks.
G. Tell Jivan “sign me out.” It should sign out immediately.
